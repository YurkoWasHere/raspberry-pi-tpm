# Alternative path: stock firmware → U-Boot measured boot (prepared, not yet tested)

An alternative to patching closed firmware: start.elf loads U-Boot instead of the kernel, and
U-Boot measures the kernel and device tree into the TPM, then boots Linux through UEFI so Linux
receives a standard TCG event log. Measured boot only: no secure boot, no OTP or boot flags, and
U-Boot's PCR re-allocation (`TPM_PCR_ALLOCATE`) is explicitly disabled.

## What's prepared

| Piece | Where | State |
|---|---|---|
| U-Boot build | `tools/uboot/` (Dockerfile, `rpi3-tpm.config`, `rpi3-tpm-softspi.dtsi`, `patches/`) | written; build must be run by the user (see below) |
| Boot tree | `srv/tftp-uboot/`, generated by `netboot/prepare-uboot-tree.sh` | ready except `u-boot.bin` |
| Tree switch | `netboot/entrypoint.sh`, `BOOT_TREE` in `netboot/.env` | written; default `tftp` = current behaviour |

### Build (run in your own terminal; the build was blocked for the assistant)

```bash
docker build --output type=local,dest=tools/uboot/out tools/uboot 2>&1 | tee /tmp/uboot-build.log
netboot/prepare-uboot-tree.sh          # copies tools/uboot/out/u-boot.bin into srv/tftp-uboot
```

The Dockerfile clones U-Boot `v2026.10` (latest release on 2026-11-25), applies the patch and
fragment, fails the build if any key option didn't take effect, and exports `u-boot.bin`,
`u-boot.dtb` and `.config` to `tools/uboot/out/`.

## U-Boot configuration (`tools/uboot/rpi3-tpm.config` on top of `rpi_3_defconfig`)

| Option | Why |
|---|---|
| `OF_SEPARATE`, `OF_BOARD=n`, `DEFAULT_DEVICE_TREE=bcm2837-rpi-3-b-plus` | U-Boot uses its own control DT, so the TPM node it needs never reaches Linux |
| `DEVICE_TREE_INCLUDES=rpi3-tpm-softspi.dtsi` | adds the TPM on bit-banged SPI to that control DT only |
| `SPI`, `DM_SPI`, `SOFT_SPI` | upstream U-Boot has no BCM2835 SPI controller driver; GPIO 11/10/9/7 are bit-banged |
| `TPM`, `TPM_V2`, `TPM2_TIS_SPI`, `CMD_TPM` | TPM 2.0 over TIS-SPI, plus `tpm2` commands for debugging |
| `TPM_PCR_ALLOCATE=n` | it would re-allocate PCR banks, a persistent TPM configuration change |
| `EFI_LOADER`, `EFI_TCG2_PROTOCOL` | `bootefi` measures the kernel and publishes the TCG2 event log in the EFI config table |
| `EFI_TCG2_PROTOCOL_MEASURE_DTB` | measures the DTB handed to Linux (see reproducibility note) |
| `EFI_VARIABLE_NO_STORE` | nowhere writable to persist EFI variables in this netboot setup |
| `BOOTDELAY=-2`, `USE_PREBOOT=n`, `BOOTSTD_BOOTCOMMAND=n` | no autoboot interrupt, no prompt: only the built-in boot command runs |
| `ENV_IS_NOWHERE`, `ENV_IS_IN_FAT=n` | no environment loaded from storage that could change the boot command |
| `CMD_UNZIP`, `CMD_FDT` | `kernel8.img` is gzip-compressed; read `bootargs` from the firmware DT |

Patch `0001-rpi-fdt_addr-prefer-firmware-dt.patch`: with a separate control DT, the rpi board
code would set `${fdt_addr}` to U-Boot's own DT. The patch sets it to the firmware-built DT
(`fw_dtb_pointer`, passed by start.elf in `x0`) whenever that is a valid FDT, so Linux gets
exactly the DT start.elf built (overlays, memory split, serial, MAC).

The board's `save_boot_params` already saves `fw_dtb_pointer`; the generic
`SAVE_PREV_BL_FDT_ADDR` option can't be used because it defines a conflicting `save_boot_params`.

### Built-in boot command

```
usb start; setenv autoload no; dhcp; setenv serverip 10.42.0.1;
tftpboot ${kernel_comp_addr_r} kernel8.img; unzip ${kernel_comp_addr_r} ${kernel_addr_r};
fdt addr ${fdt_addr}; fdt get value bootargs /chosen bootargs;
fdt rm /chosen kaslr-seed; fdt rm /chosen rng-seed;
bootefi ${kernel_addr_r} ${fdt_addr}
```

- The kernel comes over TFTP (USB LAN7515 via `USB_ETHER_LAN78XX`, already in `rpi_3_defconfig`).
- `bootargs` is copied from the firmware DT's `/chosen/bootargs`, which is what Linux gets today:
  `cmdline.txt` plus start.elf's additions (`8250.nr_uarts=1`, `vc_mem.*`, `coherent_pool`, …).
  `bootefi` passes it to the EFI stub as the load options.
- `kaslr-seed`/`rng-seed` are removed if present, since random per-boot values would make the
  DTB measurement unpredictable (`fdt rm` on a missing property just prints an error).

## Boot tree `srv/tftp-uboot/`

A copy of `srv/tftp` (same `start.elf`, `fixup.dat`, DTBs, overlays, `cmdline.txt`,
`kernel8.img`) with:
- the **stock** `bootcode.bin` (`4245ec23…`, from `bootcode.bin.orig`): no firmware measurement
  on this path, so the two approaches can be compared independently;
- `config.txt` netboot block ending in `kernel=u-boot.bin` (`arm_64bit=1`, `enable_uart=1`,
  `uart_2ndstage=1`, `dtparam=spi=on`, `dtoverlay=tpm-slb9670` unchanged);
- `u-boot.bin` (after the build).

Regenerate any time with `netboot/prepare-uboot-tree.sh`; it only reads `srv/tftp`.

## Switching trees

`BOOT_TREE` in `netboot/.env` selects what is bind-mounted over `/srv/tftp` inside the netboot
container, so the TFTP root, the NFS export and the Pi's `/boot/firmware` fstab entry
(`10.42.0.1:/srv/tftp`) follow it with no rootfs change. The entrypoint refuses
`tftp-uboot` if `u-boot.bin` is missing.

```bash
cd netboot
sed -i 's/^BOOT_TREE=.*/BOOT_TREE=tftp-uboot/' .env
docker compose up -d --build      # entrypoint changed, so rebuild the image
# back: BOOT_TREE=tftp, then docker compose up -d --build
```

## What gets measured (expected, from U-Boot's EFI TCG2 implementation; verify on the board)

| PCR | Content |
|---|---|
| 0 | U-Boot's version string (`EV_S_CRTM_VERSION`), separator |
| 1 | the DTB passed to Linux (`EFI_TCG2_PROTOCOL_MEASURE_DTB`), separator |
| 4 | the kernel's PE/COFF image (Authenticode digest, not the file sha256) and EFI boot actions |
| 7 | Secure Boot state variables (off), separator |
| 9 | possibly the command line / initrd, if the Linux EFI stub measures them (kernel-version dependent) |

Exact PCRs and events should be read from the event log rather than assumed.

## Remaining gap

On this path nothing measures `bootcode.bin`, `config.txt`, `start.elf`, `fixup.dat` or
`u-boot.bin` itself: start.elf loads U-Boot unmeasured. Closing that needs either the patched
`bootcode.bin` (covers config.txt/start.elf/fixup.dat, but not u-boot.bin) plus a start.elf patch
that measures `u-boot.bin`, or the start.elf hook (see [how-it-works.md](how-it-works.md)). The
value of this path is a standard event log and standard tooling for everything from the kernel on.

## Risks

- Soft SPI at `spi-delay-us=1` is slow, but U-Boot only sends `PCR_Extend` commands (it hashes in software).
- Warm reboots don't reset the TPM (seen on the bootcode.bin path); U-Boot treats
  `TPM_RC_INITIALIZE` as already started, and PCRs accumulate. The TPM driver supports
  `reset-gpios` if the HAT's reset line turns out to be on a GPIO.
- EFI booting changes how Linux starts (EFI stub, EFI memory map); Raspberry Pi OS kernels have
  `CONFIG_EFI=y`/`CONFIG_EFI_STUB=y`, but this has not been booted here yet.
- The firmware DT may contain other per-boot values; compare two boots' event logs before relying on PCR 1.

## Test plan (main thread)

1. Build U-Boot (above), run `netboot/prepare-uboot-tree.sh`, switch `BOOT_TREE=tftp-uboot`,
   `docker compose up -d --build`, power-cycle the Pi (clean TPM state).
2. Serial, expected order: `Raspberry Pi Bootcode` (stock, quiet), start.elf `MESS:` lines with
   `Loaded 'u-boot.bin'`, then the U-Boot banner `U-Boot 2026.10`, `TPM` / `tpm_tis_spi` probe,
   `usb start` finding the LAN7515, DHCP from 10.42.0.1, `Bytes transferred` for kernel8.img,
   `Uncompressed size`, `Booting /MemoryMapped…` / `EFI stub: Booting Linux Kernel...`, Linux boot.
3. On the Pi:
   ```bash
   ls /sys/kernel/security/tpm0/binary_bios_measurements
   sudo tpm2_eventlog /sys/kernel/security/tpm0/binary_bios_measurements   # event list + replayed PCRs
   tpm2_pcrread sha256:0,1,4,7,9
   ```
   The `pcrs:` replay at the end of `tpm2_eventlog` must equal `tpm2_pcrread`.
4. Reboot (power-cycle) a second time and diff the event logs; any DTB digest change means
   per-boot data remains in the DT.
5. Switch back with `BOOT_TREE=tftp` to return to the patched-bootcode path.
